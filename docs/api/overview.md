# API Overview

## Design Philosophy

The Typeless API is designed around **product use cases**, not raw AI model APIs. Clients interact with high-level operations (translate text, translate speech) without knowing which Sarvam model or pipeline is used internally.

### Principles

1. **Use-case driven**: Endpoints map to user actions, not provider capabilities
2. **Platform-independent**: Responses work identically for Android, iOS, Desktop
3. **Versioned**: All endpoints under `/v1/` with backward compatibility guarantees
4. **Self-documenting**: OpenAPI spec auto-generated by FastAPI
5. **Consistent errors**: Standardized error format across all endpoints

## Base URL

```
Production: https://api.typeless.app
Development: http://localhost:8000
```

## Endpoints Summary

| Method | Path | Description |
|---|---|---|
| `GET` | `/health` | Health check |
| `GET` | `/v1/languages` | List supported languages |
| `POST` | `/v1/translation` | Translate text |
| `POST` | `/v1/speech/translate` | Translate speech (upload audio) |
| `WS` | `/v1/realtime/translate` | Realtime speech translation |

## Common Headers

| Header | Required | Description |
|---|---|---|
| `X-API-Key` | Yes | Client API key for authentication |
| `X-Request-ID` | No | Client-provided request ID (auto-generated if absent) |
| `Content-Type` | Yes (POST) | `application/json` or `multipart/form-data` |
| `Accept` | No | `application/json` (default) |

## Response Format

All successful responses follow:

```json
{
  "field1": "value1",
  "field2": "value2"
}
```

All error responses follow:

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable description",
    "request_id": "req_abc123"
  }
}
```
